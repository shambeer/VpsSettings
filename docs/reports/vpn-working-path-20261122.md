## Выбранная последовательность

Следующий предлагаемый шаг — полноценный запрос через существующий VLESS/REALITY с временным клиентом и существующим доступом. Для него требуется отдельное разрешение: создаётся кратковременный тестовый процесс или контейнер. Рабочие контейнеры, пользователи и firewall меняться не должны. После проверки временные ресурсы удалить. Успех серверного теста не докажет обход ограничений мобильной сети.

Если серверный тест проходит, проверить тот же профиль на телефоне через мобильный интернет с одновременным наблюдением TCP 443. Только реальная загрузка сайтов на телефоне подтвердит выполнение пользовательской цели. При неуспехе выбрать следующий вариант по наблюдаемой причине, не считать фильтрацию ТСПУ установленным фактом.

Наличие поддержки импорта JSON XRay Reality подтверждено официальной документацией: [поддерживаемые форматы](https://docs.amnezia.org/documentation/supported-configuration-formats/). Настройки транспорта и безопасности описаны в [настройках XRay](https://docs.amnezia.org/documentation/instructions/xray-settings/). Новый VPN на сервере пока не устанавливался, серверные настройки не менялись.

Запросы HTTPS к example.com и Cloudflare trace завершились HTTP 200; trace подтвердил внешний адрес VPS. При проверке сертификатов HTTPS послаблений не было.

Исходные приватные файлы доступа в локальном private-vpn/ сохранены, как разрешено ранее; Git их игнорирует.

Этот тест подтверждает работоспособность существующего доступа и серверной цепочки VLESS/REALITY. Он выполнен с самого VPS через его публичный адрес и не проверяет путь из мобильной сети, системный VPN-режим телефона или DNS телефона. Первоначальная пользовательская проблема пока не считается решённой.

Следующий шаг для отдельного согласования: подключить на телефоне именно проверенный XRay-профиль и одновременно наблюдать поступление TCP 443 на сервере без изменения конфигурации. Если профиль ещё не добавлен, использовать private-vpn/configs/original/xray-phone.json через импорт файла подключения Amnezia. Не использовать экран импорта шаблонов серверных настроек и не публиковать профиль или ссылку доступа.

## Обход ошибки импорта файла на iPhone

Пользователь сообщил errorcode 901 при открытии JSON. Файл локально является корректным UTF-8 JSON без BOM; текущий контроллер импорта Amnezia распознаёт inbounds/outbounds как XRay, а также поддерживает ссылки vless://. Поэтому по одному коду нельзя считать сервер неисправным или утверждать, что JSON заведомо неподдерживаемый. Чтение файла на iPhone и версия приложения не проверены.

После отдельного разрешения пользователя создан локальный private-vpn/configs/original/xray-phone-qr.png из существующей ссылки xray-phone-link.txt. Проверено совпадение адреса, порта, пользователя, flow, публичного ключа, shortId и SNI с профилем, прошедшим функциональный тест. PNG проверен на точное соответствие QR-матрице; реальное сканирование iPhone пока не проверено. QR содержит доступ, исключён из Git и не передавался стороннему генератору. Сервер не менялся.

Для генерации библиотеки qrcode и pypng установлены только в private-vpn/server-settings/tools/qr-runtime. Первая попытка с Pillow не завершилась из-за отсутствия библиотеки JPEG для сборки; затем использован PNG-генератор без Pillow. Глобальные пакеты не менялись.

Пользовательский шаг: Amnezia → плюс → сканирование QR с экрана компьютера; после импорта проверить название протокола XRay. Подключение и наблюдение согласовываются после успешного импорта. Исходный код импорта: [Amnezia ImportController](https://github.com/amnezia-vpn/amnezia-client/blob/dev/client/core/controllers/selfhosted/importController.cpp).

## Подтверждённый рабочий вариант

22 ноября 2026 года, окно наблюдения 12:12:54–12:13:49 по Москве. Пользователь выполнил повторное подключение импортированного XRay-профиля через мобильный интернет и сообщил: «Выполнена, сайты открываются».

На внешнем интерфейсе сервера наблюдались два обезличенных источника TCP 443 с двусторонним обменом; внутри amnezia-xray зафиксированы установленные TCP-соединения. Суммарные счётчики включают посторонний трафик и не доказывают принадлежность конкретных потоков телефону. В этой версии счётчика чистые входящие SYN учитывались только при точном флаге S, поэтому варианты с дополнительными флагами могли не попасть в in_syn; по этому счётчику нельзя оценивать долю успешных установлений соединений. Подтверждение пользовательского результата — именно открытие сайтов на телефоне, дополненное ранее выполненным успешным тестом серверной цепочки.

Рабочий способ: существующий Amnezia XRay, VLESS/REALITY, TCP 443, профиль из private-vpn/configs/original/xray-phone-link.txt, импортированный через вставку ключа. Установка нового VPN, изменение firewall, новых пользователей и перезапуск рабочего сервера для этого результата не потребовались.

Оставить на телефоне выбранным проверенный профиль XRay. AmneziaWG этим не исправлен; его исправление не требуется для использования подтверждённого рабочего XRay. Работоспособность подтверждена на этом телефоне через мобильную сеть в указанной попытке; остальные устройства, Wi-Fi и долговременная стабильность не проверены. Приоритетная цель пользователя — получить работающий VPN — достигнута для проверенного сценария. Прежние задачи обслуживания и создания полного скрипта восстановления остаются отдельной незавершённой работой.

## Wi-Fi: пользовательская цель ещё не полностью достигнута

После успешной мобильной проверки пользователь сообщил, что через Wi-Fi XRay не работает. Поэтому результат нельзя распространять на все сети; требуется дальнейшая работа.

Повторное наблюдение согласовано пользователем. Окно 22 ноября 2026 года 12:16:20–12:17:15 по Москве, Wi-Fi с выключенными мобильными данными. Пользователь подтвердил: «Подключено, но сайт не открывается».

Зафиксированы два обезличенных источника. Основной: 401 входящий и 1219 исходящих пакетов, 133 входящих SYN и 133 исходящих SYN-ACK, 193602 входящих и 40910 исходящих байт TCP payload, 924 исходящих пакета с FIN, RST не наблюдались. Второй: только 9 исходящих пакетов, 567 байт payload. Счётчики учитывают повторные передачи; количество FIN не является количеством отдельных завершённых соединений. В этом тесте входящие SYN с дополнительными флагами учитывались. Принадлежность источников телефону независимо не установлена, поэтому суммарный трафик не является доказательством конкретного клиентского handshake. Содержимое трафика не сохранялось.

Различие результатов по сетям подтверждено пользователем. Конкретная причина — фильтрация пути, особенности клиентского TLS, маршрутизация или другая — пока не установлена. Рабочие серверные настройки не менялись. Следующий возможный обратимый эксперимент: отдельный клиентский профиль того же доступа с другим поддерживаемым TLS fingerprint, сохранив рабочий исходный профиль. Изменение fingerprint не гарантирует решения и требует отдельного согласия.
