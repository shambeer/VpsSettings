## Предварительный анализ

- ОС сообщает Ubuntu 26.04.1 LTS. Docker установлен из Ubuntu-пакета docker.io, версия сервера 29.1.3; containerd и Compose также установлены из системных пакетов. Не следует смешивать это с переустановкой через get.docker.com.
- Оперативная память: около 1054 MiB, доступно около 563 MiB на момент проверки. Используется около 356 MiB swap из 2047 MiB. Корневой раздел: около 20 ГБ, свободно около 7.1 ГБ. Значения относятся к моменту инвентаризации.
- Ядро в работе: 7.0.0-42-generic. Пакет 7.0.0-43-generic уже установлен. До согласованной перезагрузки нужно проверить сохранность VPN и наличие нужного модуля AWG для нового ядра.
- systemctl не показывает failed units. Это не подтверждает работоспособность каждого VPN-подключения.
- Симуляция APT по существующему кэшу предлагает 30 обновлений и 4 отложенных phased-обновления. apt update не запускался, поэтому это не окончательный актуальный список. Удержанных через apt-mark пакетов нет.
- Docker сообщает 10 контейнеров и 10 образов. Обобщённый показатель reclaimable не является списком безопасного удаления; массовый prune не предлагается.
- В инвентаризации AWG имеет только bind /lib/modules, а XRay не имеет внешних томов. Их рабочие конфигурации находятся в файловой системе контейнеров. Сохранение только исходных образов или docker inspect не сохранит изменённые конфигурации.
- 3x-ui хранит /etc/x-ui в анонимном томе. Нельзя потерять его при пересоздании, подставив только каталог /root/3x-ui/db, который фактически смонтирован в /etc/xray.
- PostgreSQL 18 хранит данные в отдельном томе. Для резервной копии базы нужен согласованный дамп; простое копирование работающего PGDATA не заменяет согласованный backup.
- Не-VPN пакеты мониторинга Loki/Grafana/Promtail среди системных пакетов не обнаружены: этот стек контейнерный. Назначение snapd, LXD, ModemManager и служебных пакетов ещё требует проверки зависимостей и использования. Системные, дисковые, сетевые, SSH-, Docker-, TLS- и защитные пакеты не объявляются лишними только потому, что в их названии нет VPN.

Поддержать сохранение существующих ключей и клиентов, проверку домена и конфликтов портов. Не обещать восстановление старых доступов без соответствующего резервного архива.

## Готовность к отдельной перезагрузке

Перед согласованной перезагрузкой сервер работал на 7.0.0-42-generic; needrestart ожидал 7.0.0-43-generic. Проверено наличие /boot/vmlinuz-7.0.0-43-generic и /boot/initrd.img-7.0.0-43-generic, размер initramfs около 33.9 МБ.

Docker включён в автозапуск, все семь контейнеров имеют restart_policy=always. SSH использует включённый ssh.socket при отключённом ssh.service, что соответствует socket activation; само по себе это не ошибка. systemd-networkd включён.

Перед перезагрузкой needrestart перечислял службы, ещё использующие прежние библиотеки, включая Docker/containerd и Fail2ban. Проверки после фактической загрузки нового ядра описаны ниже.

## Дополнительное сетевое препятствие 3x-ui

После запуска ядра netstat внутри контейнера показывает реальные VPN-listeners, но Docker публикует только 2053/tcp. Контейнер работает в bridge. На хосте эти VPN-listeners не появились; публикация соответствующих VPN-портов в проверенной конфигурации Docker отсутствует. Само исправление TLS поэтому не делает профили 3x-ui доступными из внешней сети.

3DP использует случайные порты 10000–59999 и меняет их при ротации. Статически опубликовать только текущий набор недостаточно для постоянного решения. Его текущий getFreePort проверяет таблицу inbound и текущий batch, но не занятость портов другими процессами хоста. Поэтому переход к host network требует также продуманного firewall и предотвращения конфликтов с Amnezia/Telemt; простой проброс широкого диапазона через Docker может конфликтовать с уже занятыми портами.

Сетевой режим, UFW и публикация портов в этом шаге не менялись. Постоянное решение будет согласовано отдельно. Фактические listeners и публикация: [post-tls-network-audit.json](evidence/inventory/post-tls-network-audit.json).
