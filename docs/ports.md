# Порты VPS Migration

Проверено по текущему коду 28.11.2026. Это схема по умолчанию, а не результат проверки слушателей реального VPS. При восстановлении из копии и через --options публичные порты могут отличаться.

## На основном сервере

| Порт | Протокол | Назначение | Доступность |
| --- | --- | --- | --- |
| 22 либо выбранный SSH-порт | TCP | SSH, управление и миграция | Снаружи; порт задаётся отдельно для каждого VPS |
| 80 | TCP | Nginx: ACME HTTP-01/webroot и перенаправление на HTTPS новых способов | Снаружи в полном режиме |
| 443 | TCP | Amnezia XRay / прежний VLESS REALITY | Прямой вход Amnezia |
| 46872 | UDP | AmneziaWG, amnezia-awg2 | Снаружи в all; в filtered локальная публикация |
| 50553 | TCP | Telegram MTProxy, amnezia-telemt | Снаружи в all; в filtered локальная публикация |
| 8443 | TCP | HAProxy → новый VLESS TLS/Vision, XHTTP/TLS, TLS/WARP; сайт и HTTPS-подписки | Снаружи |
| 8443 | UDP | Новый Hysteria2 с TLS и Salamander | Снаружи |
| 8444 | TCP | HAProxy → новый REALITY на свой сайт: RAW/Vision, XHTTP/REALITY, REALITY/WARP | Снаружи, если REALITY включён |
| 2053 | TCP | Админ-панель 3x-ui | 127.0.0.1; открывается через SSH-туннель |
| 6659 | TCP | HTTPS панели 3DP | Снаружи в all; в filtered локальная публикация |
| 51820 | UDP | Резервный WireGuard | Снаружи в all; в filtered локальная публикация |
| 1194 | UDP | Резервный OpenVPN | Снаружи в all; в filtered локальная публикация |
| 8388 | TCP и UDP | Shadowsocks: personal | Снаружи в all; в filtered локальная публикация |
| 8389 | TCP и UDP | Shadowsocks: shared | Снаружи в all; в filtered локальная публикация |
| 2443 | UDP | Прежний резервный Hysteria2 | Если восстановлен из копии или Self-Steal выключен; новый одинаковый экземпляр не создаётся |

WARP не занимает отдельный публичный вход: клиент использует профиль на 8443 или 8444, а сервер направляет только его трафик через WireGuard-выход Cloudflare. Адрес/порт исходящего узла берутся из ответа регистрации WARP; это не серверный слушатель.

UDP 443 может сохраняться в восстановленной конфигурации Amnezia. При новой установке Amnezia XRay публикует только TCP 443; присутствие UDP 443 в списке пересылки relay само по себе не означает наличие слушателя.

Повторение номера внутри разных контейнеров допустимо: у них разные сетевые пространства. Например, внутренний 443 нового Xray не отбирает внешний 443 Amnezia. TCP 8443 и UDP 8443 также являются разными слушателями.

## Российский relay

У relay собственный выбранный SSH-порт. На него пересылаются опубликованные VPN-порты к основному VPS; правило пересылки не является отдельным VPN-процессом. В filtered пересылаются TCP 80, 443, 8443, 8444 и UDP 8443 при полном режиме по умолчанию. В all добавляются порты прежних VPN/3DP и публичные порты из копии.

SSH-порт relay не должен совпадать с пересылаемым TCP-портом. Один и тот же SSH-порт на двух разных серверах допустим.

## Конфликты и проверки

В стандартной схеме назначения не конфликтуют. Перед установкой программа проверяет слушатели целевого VPS; relay отдельно проверяет занятые и пересылаемые порты. Цель установки должна быть чистой.

При восстановлении новые порты выбираются с учётом публичных и loopback-привязок копии; при необходимости используется диапазон 8443–8543. Явно заданные порты не должны пересекаться с сохранёнными приложениями и друг с другом. Если HTTP 80 занят другим сохранённым приложением, полный webroot-режим останавливается, а не вытесняет сервис.

Это не доказательство отсутствия любых конфликтов в произвольной копии: необычные host/container network-схемы требуют ручного переноса, а сторонний администратор может занять порт после проверки. Фактическое состояние конкретного VPS в этой проверке не исследовалось.

Sub-Store: внешний доступ к панели отсутствует. Внутренние TCP3000(API),3001(frontend); frontend публикуется только на127.0.0.1:43000–43099 (свободный порт выбирается при установке). Открывать через сохранённый SSH-туннель. Пользовательская выдача использует существующий HTTPS-порт новых способов.
