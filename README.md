# VPS Settings

Интерактивные сценарии установки, резервного копирования и миграции VPN-стека.

Два режима подключения: **1 — один VPS без российского сервера; 2 — основной VPS через российский relay**. В обоих режимах прежние VPN сохраняются, сверху добавляются Self-Steal, VLESS TLS/XHTTP и Hysteria2 на 443. PostgreSQL остаётся. Мастер оформлен блоками с нумерованными вариантами и подсказками Enter. [Схема и подробности](scripts/migration/README.md#два-режима-один-vps-или-основной-vps-через-российский-relay).

## Начать здесь: что открыть и что вводить

**Запускайте мигратор на своём компьютере, где хранится приватный SSH-ключ.** Он сам подключится к серверам. Не требуется сначала заходить на новый VPS и переносить туда свой приватный ключ.

Общий установщик и релизы: [VpsMigration](https://github.com/shambeer/VpsMigration). Репозиторий клонировать не требуется. Нужны Python 3.11+ и OpenSSH на компьютере, для Linux также curl и Bash.

### 1. Windows PowerShell

```powershell
& ([scriptblock]::Create((New-Object Net.WebClient).DownloadString('https://github.com/shambeer/VpsMigration/releases/latest/download/run.ps1')))
```

Для проверки скачивания и синтаксиса без подключения к серверу добавьте `--check` в конец команды. Приватный SSH-ключ указывается локальным путём в меню; содержимое ключа никуда не вставляйте.

### 2. Linux или установленная WSL

```bash
curl -fsSL https://github.com/shambeer/VpsMigration/releases/latest/download/run.sh | bash
```

Команду вводить в терминале Linux/WSL, а не в PowerShell. Для проверки без SSH: `curl -fsSL https://github.com/shambeer/VpsMigration/releases/latest/download/run.sh | bash -s -- --check`.

Оба запускателя скачивают конкретную версию Python-пакета, проверяют встроенный SHA-256 и открывают меню. Выполняемый запускатель требует доверия к владельцу публикации и GitHub. Сначала можно скачать и прочитать его. Из исходников по-прежнему доступно `python -X utf8 scripts/migration/migrate.py`.

### 3. Что выбрать в меню

| Пункт | Когда выбирать |
| --- | --- |
| 1 — Новая установка | Чистый сервер и новые личные/общие VPN-доступы. |
| 2 — Миграция | Перенос существующих доступов: свежая полная копия старого сервера либо ранее созданный migration-bundle.tar.gz. |
| 3 — Только копия | Сохранить полный снимок, не разворачивая новый сервер. |

Далее сценарий спросит IP, домен, SSH-порт и **путь к файлу приватного ключа**, а не текст ключа. Для режима миграции понадобятся также данные старого сервера или архив с его SHA-256. Изменения начинаются после явных подтверждений BACKUP/DEPLOY с указанным IP.

Перед реальным развёртыванием: чистый Linux x86_64, Ubuntu 24.04/26.04 или Debian 12/13, root-вход по ключу, Python 3.11+ на сервере, домен с A-записью на IPv4 входа (relay либо основного VPS) без AAAA. Подробности по ресурсам, портам, DNS и ограничениям — в [полной инструкции](scripts/migration/README.md).

### 4. Где будут конфиги и строки

В начале выберите один из трёх вариантов: **1 — Рабочий стол, 2 — Документы (по умолчанию), 3 — свой путь**. На Windows учитываются системные перенаправления папок, включая OneDrive.

Все файлы операции сохраняются в `<выбранная папка>/VpsMigration/<дата-id>/`. Бэкап — `migration-bundle.tar.gz`, рядом `backup-result.json` с SHA-256. Конфиги и строки — в `access/personal/` и `access/shared/`, внутри раздельные `configurations/` и `strings/`. `admin/` и `legacy/` не раздавать. Полный путь показывается до подключения к серверу и после завершения. Старые бэкапы не перемещаются.

**Сквозная установка и восстановление на чистом VPS ещё не испытаны.** Сначала нужен пробный сервер и отдельный тестовый домен; не отключайте старый VPS до проверки нового. Создание копии временно останавливает выбранные сервисы.

## Возможности

- Новая установка либо перенос пользователей и ключей из полной резервной копии.
- XRay/REALITY, AmneziaWG, Telegram MTProxy и панели 3x-ui/3DP.
- Резервные WireGuard, OpenVPN, Shadowsocks и Hysteria2.
- Настройка SSH по ключу, Fail2ban и экспорт личных/общих конфигураций.
- Переносимый пакет для запуска без Git; загрузчик проверяет SHA-256 пакета.

## Проверка

```sh
python scripts/migration/migrate.py --check
python -m unittest discover -s scripts/migration/tests
```

Локальные тесты не заменяют пробную миграцию на чистую машину. Полный deploy/restore на отдельном VPS пока не испытан. Новый сценарий требует собственной полной копии; архивы отдельных операций не являются её заменой.

Никакие действующие адреса, домены, SSH-отпечатки и конфиги конкретного сервера в этом README не публикуются. Не добавлять в Git private-vpn/, файлы доступов и резервные архивы. Исключение из Git не шифрует локальные материалы и не удаляет ранее опубликованное из истории.

В меню также есть пункт **4 — обслуживание существующего VPS**: полное обновление пакетов текущей ОС или выборочная очистка Docker/APT. Перед изменениями показывается план и запрашивается отдельное подтверждение; создаются приватные копии настроек. Перезагрузка согласуется отдельно. Универсальное обновление образов/major PostgreSQL не выполняется. Подробнее — в инструкции мигратора. Реальное Linux-испытание обслуживания ещё требуется.
