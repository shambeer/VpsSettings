# VPS Settings

Интерактивные сценарии установки, резервного копирования и миграции VPN-стека.

## Начать здесь: что открыть и что вводить

**Запускайте мигратор на своём компьютере, где хранится приватный SSH-ключ.** Он сам подключится к серверам. Не требуется сначала заходить на новый VPS и переносить туда свой приватный ключ.

**Текущий статус:** запуск из локальных файлов доступен. Пакет для запуска без клонирования подготовлен, но релиз ещё не опубликован — рабочей удалённой команды curl пока нет. Для приватного релиза дополнительно нужна авторизация GitHub; обычный анонимный curl его не скачает.

### 1. Если вы в Windows PowerShell

Откройте папку проекта в терминале PowerShell и выполните:

```powershell
python -X utf8 scripts/migration/migrate.py
```

Нужны Python 3.11+ и системные команды ssh/scp. Версию Python можно проверить командой `python --version`. Если команда не найдена, сначала установите Python/OpenSSH; сам мигратор их на компьютере не устанавливает.

В обычном PowerShell команда с `| bash` не работает без Bash/Linux-окружения. Не путайте `curl.exe` для скачивания файлов с возможностью выполнять Linux-скрипты.

### 2. Если вы в Linux или уже установленной WSL

Откройте терминал Linux. В Windows для WSL откройте терминал установленного Linux-дистрибутива, например Ubuntu, а не PowerShell.

Если файлы проекта уже на компьютере, из его корня выполните:

```bash
sh scripts/migration/deploy.sh
```

Для будущего запуска без клонирования будет использоваться схема `curl -fsSL <URL опубликованного run.sh> | bash`. **Это пример формата, не готовая команда: текст в угловых скобках нельзя копировать как рабочий адрес.**

После публикации нужно скопировать точную команду соответствующего релиза, вставить её в терминал Linux/WSL и нажать Enter. curl скачает запускатель, Bash выполнит его, запускатель загрузит переносимый пакет, проверит его SHA-256 и откроет меню. Нужны curl, Bash, Python 3.11+ и ssh/scp; Git и клонирование не нужны. Для вопросов скрипту требуется интерактивный терминал.

Владельцу проекта: сборка `python scripts/migration/build_portable.py` создаёт точные строки в dist/migration/run-linux.txt и run-windows.txt. Эти адреса заработают только после загрузки соответствующих файлов в GitHub Releases. Для анонимного curl нужен публично доступный несекретный пакет; весь основной репозиторий ради этого открывать не требуется. Для приватной публикации сначала нужно настроить вариант с авторизацией, а не вставлять токен в публичный README.

### 3. Что выбрать в меню

| Пункт | Когда выбирать |
| --- | --- |
| 1 — Новая установка | Чистый сервер и новые личные/общие VPN-доступы. |
| 2 — Миграция | Перенос существующих доступов: свежая полная копия старого сервера либо ранее созданный migration-bundle.tar.gz. |
| 3 — Только копия | Сохранить полный снимок, не разворачивая новый сервер. |

Далее сценарий спросит IP, домен, SSH-порт и **путь к файлу приватного ключа**, а не текст ключа. Для режима миграции понадобятся также данные старого сервера или архив с его SHA-256. Изменения начинаются после явных подтверждений BACKUP/DEPLOY с указанным IP.

Перед реальным развёртыванием: чистый Linux x86_64, Ubuntu 24.04/26.04 или Debian 12/13, root-вход по ключу, Python 3.11+ на сервере, домен с A-записью на новый IPv4 без AAAA. Подробности по ресурсам, портам, DNS и ограничениям — в [полной инструкции](scripts/migration/README.md).

### 4. Где будут конфиги и строки

После запуска из исходников: private-vpn/server-settings/migrations/<дата-id>/access/. Внутри personal/ и shared/ раздельные каталоги configurations/ и strings/. Файлы admin/ и legacy/ не раздавать вместе с общим доступом.

У переносимого пакета та же структура находится в локальной папке его версии: Windows — LOCALAPPDATA/VpsSettings/migration/, Linux/WSL — ~/.local/share/VpsSettings/migration/ либо XDG_DATA_HOME/VpsSettings/migration/. Полный путь выводится в терминал. Это папки на компьютере, с которого запущен мигратор, а не публичный GitHub-репозиторий.

**Сквозная установка и восстановление на чистом VPS ещё не испытаны.** Сначала нужен пробный сервер и отдельный тестовый домен; не отключайте старый VPS до проверки нового. Создание копии временно останавливает выбранные сервисы.

## Возможности

- Новая установка либо перенос пользователей и ключей из полной резервной копии.
- XRay/REALITY, AmneziaWG, Telegram MTProxy и панели 3x-ui/3DP.
- Резервные WireGuard, OpenVPN, Shadowsocks и Hysteria2.
- Настройка SSH по ключу, Fail2ban и экспорт личных/общих конфигураций.
- Переносимый пакет для запуска без Git; загрузчик проверяет SHA-256 пакета.

## Проверка

```sh
python scripts/migration/migrate.py --check
python -m unittest discover -s scripts/migration/tests
```

Локальные тесты не заменяют пробную миграцию на чистую машину. Полный deploy/restore на отдельном VPS пока не испытан. Новый сценарий требует собственной полной копии; архивы отдельных операций не являются её заменой.

Никакие действующие адреса, домены, SSH-отпечатки и конфиги конкретного сервера в этом README не публикуются. Не добавлять в Git private-vpn/, файлы доступов и резервные архивы. Исключение из Git не шифрует локальные материалы и не удаляет ранее опубликованное из истории.
